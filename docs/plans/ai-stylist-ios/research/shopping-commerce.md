## 0. Executive summary (decision-relevant)

1. **There is no "search the whole web by image" API that is both official and fashion-grade.** Bing Visual Search is dead (retired 2025-08-11). Google Lens has no official API; the practical route is a SERP-scraping wrapper (SerpApi `engine=google_lens`, `type=products|visual_matches|exact_matches`) at ~$7–25 per 1,000 searches on subscription tiers. Gemini's `google_search` grounding is text-only search (image_search returns images for a text query; it does not do reverse image lookup) — it is good for "where to buy a similar X" after Gemini has described the garment, not for exact-item identification. Syte/ViSenze/Lykdat search a catalog *you* supply (or Lykdat's own index); they are retailer tools with unpublished pricing.
2. **Amazon is effectively closed to a new app.** PA-API 5 is retired (docs banner: deprecated 2026-05-15; final email cutoff reported 2026-06-30; new registrations refused). Its successor, the **Creators API**, requires an approved Associates account **plus ≥10 qualifying sales in the trailing 30 days per region** (access suspends after 30 days without sales), and Associates itself closes new accounts that do not make **3 qualifying sales within 180 days** (Operating Agreement update 2026-04-14). Plan Amazon as a Phase-2 nice-to-have, not a dependency.
3. **The fastest legal monetization is a link-wrapper network** (Skimlinks: free, ~25% of commission, no traffic threshold; Sovrn Commerce: self-serve) — they monetize *any* merchant URL you already show, with no per-merchant approval. Real catalogs with search APIs (Impact.com `Catalogs/ItemSearch`, Rakuten `productsearch/1.0`, CJ GraphQL `products`, Tradedoubler Products API) need publisher approval + per-advertiser joins; Awin (EU-strongest, 30k+ advertisers, ShareASale absorbed 2025-10) is **feed-download only** (no keyword search API) and needs a £5/$1 refundable deposit + manual review.
4. **Google Merchant Center / Content API is not a product-search source for a third-party app**: Content API v2.1 is deprecated (discovery doc text) with sunset reported for 2026-08-18; the Merchant API only manages *your own* merchant account. Pinterest's API v5.28 has no visual search and its only cross-user pin search (`/search/partner/pins`) is beta and "not available to all apps".
5. **Apple is not a blocker for physical-goods commerce**: Guideline 3.1.3(e) says apps enabling purchase of physical goods "must use purchase methods other than in-app purchase". Affiliate links opened in `SFSafariViewController` are standard. The real Apple constraints are 5.1.2(i) (explicit consent before sending user photos to third-party AI / SerpApi), ATT if you pass user-level IDs in affiliate sub-IDs, and 3.1.1 for any digital "credits".
6. **FTC 16 CFR 255.5** requires a clear-and-conspicuous disclosure of the commission relationship near the recommendation itself; EU UCPD/Omnibus adds ranking-transparency duties if you rank products; Amazon requires its exact disclosure sentence.
7. **Image licences are the hidden trap**: Awin licences advertiser images "without modifications", CJ forbids altering graphics, Amazon forbids caching images (hotlink ≤24h) — so **you cannot run virtual try-on on affiliate product images** without a direct brand deal. Only user-supplied screenshots are safe for VTO.
8. **Competitors**: Essembl shipped "Item Finder" (photo/screenshot → matches + shop links, 2025-12) and "Shopping Buddy" (wardrobe-aware chat recommendations, 2026-07); users still ask for "better and more variety of shopping recommendations" — i.e. its catalog is thin. Alta is free and affiliate-funded (Rakuten/Sovrn dept-store programs; wishlist with price-drop alerts; brand B2B try-on deals). Whering has a "100M+" retailer item DB + Chrome extension, funded by eBay Ventures (resale roadmap). Google killed Doppl (2026-04-30) and folded try-on + agentic checkout (UCP, Universal Cart) into Search/Shopping.
9. **Recommended MVP**: Gemini vision → structured garment description → (a) SerpApi Google Lens `type=products` on a cropped, EXIF-stripped garment image for exact/near matches and (b) Gemini `google_search` grounding for "where to buy similar" fallback; wrap every outbound link with Skimlinks/Sovrn; Shopping Buddy = Gemini + wardrobe RAG + grounding, no catalog; wishlist = URL → JSON-LD/`url_context` extraction with manual "re-check price". Defer networks-with-feeds (Awin/Impact/CJ/Rakuten) and price tracking to Phase 1, Amazon and agentic checkout (UCP/ACP) to Phase 2.

**Practical accuracy notes.** (i) Crop to the single garment (Gemini bounding boxes / segmentation → crop) before Lens; whole-outfit images return mixed results. (ii) Run Lens with `country` = user's storefront (US/UK/DE/IL) — merchant coverage differs. (iii) Use Gemini's structured description (brand, colour, category, pattern, material, price tier) to (a) re-rank Lens results, (b) generate the grounding query, (c) filter results to shoppable domains. (iv) Expect "dupe" rather than "exact" for unbranded basics; label results honestly ("similar", "exact match").

**Cost per shop-the-look action (MVP):** SerpApi $0.010–0.025 + Gemini vision ≈ $0.001–0.003 + optional grounding $0.014 → **≈ $0.02–0.04 per find**. At 20 finds/user/month ≈ $0.40–0.80 — fine behind a paid tier, too expensive to give away unlimited on free.

## 3. Price tracking & wishlist patterns

**Data sources for prices**
- Affiliate feeds carry `price`, `sale_price`/`store_price`, RRP, `in_stock`, `stock_quantity`, `delivery_cost` and refresh on the advertiser's cadence (Awin list exposes `Last Imported` for conditional download) [H — Mercaria awin.md]. This is the only *licensed* bulk price source.
- Impact/CJ/Rakuten search APIs return current price per query — fine for on-demand "re-check price" but rate-limited for fleet-wide polling (Impact 3,000/h; CJ 500/5 min; Rakuten 100/min).
- Amazon: prices must come from the API, may be cached ≤24 h then refreshed, ASINs storable indefinitely, image bytes never cached (URL ≤24 h), and **a timestamp + disclaimer must sit next to any price refreshed less often than hourly**; scraping is forbidden by the Associates licence [H — Program Policies quoted verbatim in hw-radar]. Keepa/CamelCamelCamel already own Amazon price history.
- eBay: displayed listing data must be ≤6 h old, other content ≤24 h; delete when no longer public; no AI training [M — hw-radar/Mercaria].
- Google Programmable Search / grounding results may not be stored non-transitorily [M — hw-radar quoting Google terms].
- Arbitrary retailer URLs (user pastes a Zara link): fetch on the user's request and parse schema.org `Product`/`Offer` JSON-LD or use Gemini `url_context` (≤20 URLs/prompt) to extract name/price/currency/image/availability [H — gemini-vision.md §8]; Lykdat offers the same as `extractProduct(url)`. Automated re-polling of retailer pages is a ToS/anti-bot problem — keep it user-triggered or low-frequency, and prefer feed/API sources where available.

**Design patterns (borrowed from Mercaria's production docs, 2026-08)** [H for the pattern, source: OxyHQ/Mercaria docs/price-alerts.md, watchlists.md, shopping-agents.md]
- Trigger identity = (alert, offer, **observed-price-version**, policy version) with `ON CONFLICT DO NOTHING` → a re-read of the same price never re-notifies; a timestamp in the key would fire every sweep.
- "Unknown never satisfies": an alert on *delivered total* cannot fire if delivery cost is unpublished; `in_stock` requires a positive statement.
- Repeat policies: `once`, `reset_threshold` (re-arm when price climbs back above target), `cooldown_better_low` (materially lower after cooldown), `always`.
- Watchlist basket totals: convert every line to the display currency with the FX snapshot, one basis (delivered vs item price) for the whole total, explicit `complete/partial/unknown` states, never claim a multi-store optimum.
- Saved "shopping agents" (standing objectives) that can only *look*, never buy; evaluation keyed on a digest of inputs; notify once per qualified finding.

**Wishlist UX in the category** (competitors.md matrix): Whering lookbooks/wishlists; Indyx wishlist; Alta wishlist **with price-drop alerts** and gap analysis (App Store listing 2026-07 [H — loomies-15]); Acloset wishlist + "does this fit my closet"; Pureple wished items; GetWardrobe-style "4K brands + price alerts". Table-stakes: save from URL/share sheet, screenshot import, "I own something similar" check, cost-per-wear projection.

**Wishlist item schema (recommended):** `source_url`, `merchant_host`, `network` (skimlinks/sovrn/awin/…), `external_id` (ASIN/SKU/GTIN when known), `title`, `brand`, `price{amount,currency,observed_at,version}`, `image_url` (+ licence flag: user-uploaded vs merchant hotlink), `availability`, `size/colour`, `embedding`, `last_checked_at`, `alert{target,policy,armed_at}`.

## 5. Legal & platform rules

### 5.1 FTC (US)
- **16 CFR §255.5(a)** (Endorsement Guides, revised 2023): a material connection "that might materially affect the weight or credibility of the endorsement, and that connection is not reasonably expected by the audience … must be disclosed clearly and conspicuously"; "a disclosure … must clearly communicate the nature of the connection". [H — eCFR text (2025-02-06 snapshot) in github.com/lucas-amberg/ecfr-analyzer and AlextheYounga/ecfr]
- Practical: put "We may earn a commission when you buy through links" **adjacent to the recommendation list / on the product card**, not only in Settings/ToS; keep it visible in the chat surface where Shopping Buddy recommends; do not let paid placement influence ranking without saying so. FTC's Consumer Reviews & Testimonials Rule (effective 2024-10-21) also bans fake/AI reviews — relevant if you ever show "reviews".
- **Amazon** requires the exact sentence "As an Amazon Associate I earn from qualifying purchases" on Associates sites/apps [M — Operating Agreement, well known; page blocked].

### 5.2 EU
- UCPD 2005/29/EC Annex I(11) (advertorial without disclosure), Art. 6/7; **Omnibus Directive 2019/2161** added Art. 7(4a): when you let consumers search products, disclose the *main parameters determining ranking* and any paid ranking. [M — memory; verify wording]
- DSA Art. 26 (ad labelling on online platforms) applies if you host UGC/ads. GDPR: wardrobe photos are personal data; body photos for try-on may be treated as sensitive-adjacent — explicit consent and deletion path (Apple 5.1.1(v) also requires in-app account deletion).

### 5.3 Israel
- Consumer Protection Law 5741-1981 §7(c) prohibits advertising not identifiable as such; general duty not to mislead [L — memory]. Privacy Protection Law amendments (2024/25) tightened data-processing duties [L]. Verify with local counsel.

### 5.4 Apple App Review Guidelines (text from local `ios/guidelines.txt`, current)
- **3.1.3(e) Goods and Services Outside of the App:** "If your app enables people to purchase physical goods or services that will be consumed outside of the app, you **must use purchase methods other than in-app purchase** to collect those payments, such as Apple Pay or traditional credit card entry." → affiliate links / merchant checkout / Apple Pay are the *required* path for clothes. [H]
- **3.1.3 preamble:** apps in 3.1.3 "cannot, within the app, encourage users to use a purchasing method other than in-app purchase, except for apps on the United States storefront and as set forth in 3.1.1(a) and 3.1.3(a)" — this concerns *digital* content; physical goods are carved out by (e). Keep any subscription/credits on IAP (3.1.1; consumable credits must not expire — ios-platform.md). [H]
- **5.1.2(i):** "clearly disclose where personal data will be shared with third parties, **including with third-party AI**, and obtain explicit permission" → consent screen before sending photos to Gemini/SerpApi; App Privacy label. Also explicit ATT permission "to track"; do **not** pass user-level identifiers in affiliate sub-IDs (`xcust`, `subId1`, `clickref`) unless you treat it as tracking — use per-click random IDs. [H for text; M for the sub-ID interpretation]
- **5.1.2(vi):** data from depth/facial mapping/Photo APIs may not be used for marketing/advertising — don't build ad profiles from wardrobe photos. [H]
- **2.5.18** ads only in main binary; no sensitive-data targeting. [H]
- Outbound links: open affiliate redirects in `SFSafariViewController` (or `ASWebAuthenticationSession`-style) so the network's redirect → merchant cookie chain completes; if the merchant has Universal Links, iOS may hand off to the merchant *app* mid-redirect and break cookie attribution — use networks with app-to-app support (Impact mobile deep links; Amazon `detailPageURL` opens the Amazon app with the tag preserved) or force in-app web for attributed clicks. **SKAdNetwork/AdAttributionKit are irrelevant** here (they attribute *app installs* from ads, not web purchases). [M — engineering knowledge; local Apple docs cover SKAdNetwork only]

### 5.5 Amazon Associates / Creators API rules for a mobile app
- PA-API 5 retired; new integrations must use Creators API; eligibility 10 qualifying sales/30 days per region; Associates account requires 3 sales/180 days (2026-04-14 update). [H]
- "You will not use Creators API, PA API, Data Feeds, or Product Advertising Content with any site or application … that does not have the principal purpose of advertising and marketing an Amazon Site and driving sales" — a general stylist app must ensure the Amazon surface is clearly promotional. [H — Program Policies quoted verbatim, ChocoData/amazon-scraper README, "Updated: April 14, 2026"]
- Caching: ASINs indefinitely; non-image content ≤24 h then refresh; images never cached, links ≤24 h; prices with timestamp/disclaimer if refreshed less than hourly; every image must link to Amazon; no data mining/robots. [H]
- Apps must be registered as an Associates "site"; links may not be used in emails/offline; link cloaking forbidden. [M — memory of Operating Agreement]

### 5.6 Image licences vs. virtual try-on (cross-feature warning)
Awin: licence to publish advertiser material **"without modifications"**; CJ: expressly forbids copying/modifying graphics; Rakuten: no explicit image licence; Amazon: no caching, hotlink only; eBay: delete when unavailable, no AI training; **none grant training or derivative-work rights** [M — capsulezero §7.3 read the agreements; hw-radar/Mercaria for eBay/Amazon]. Consequence: "try this recommended product on me" must use either (a) user-uploaded screenshots, (b) brand-partner images under a direct licence (Alta's model), or (c) images from networks whose terms you have cleared in writing.

## 7. Recommended phased approach

### Phase 0 — MVP (weeks; zero partner approvals)
**Shop-the-look**
1. Gemini 3.x Flash vision: detect garments (bounding boxes) → user taps the item → crop, strip EXIF, blur faces if present → structured description JSON `{category, colour, pattern, material, brand?, price_tier, style_tags}`.
2. SerpApi `engine=google_lens&type=products&country=<user>&hl=<lang>` on the crop (upload to a signed URL with ≤10 min TTL, delete after). Parse `visual_matches`/products (title, link, source, price, thumbnail). Re-rank with the Gemini description; filter to merchant domains; label "exact/similar".
3. Fallback/expansion: Gemini `google_search` grounding with the description ("buy <brand> <colour> <item> <country>") → grounded links (+ mandatory Search entry point rendering) → optional `url_context` to pull price/size.
4. Monetize every outbound link via **Skimlinks Link Wrapper** (`go.skimresources.com/?id=&url=&xcust=<random click id>`) or Sovrn; show FTC disclosure on the results screen; open in `SFSafariViewController`.
5. Meter: e.g. 10 finds/month free, unlimited on subscription (cost ≈ $0.02–0.04/find).

**Shopping Buddy (wardrobe-aware)**
- Wardrobe RAG: item embeddings (`gemini-embedding-2`, image+caption → 768–1536-d) + structured attributes in your DB; retrieval of the 20–40 most relevant items + user style profile + occasion → Gemini prompt that must (a) say what the wardrobe already covers ("you own 3 navy blazers"), (b) recommend ≤3 *gaps* with concrete search specs, (c) generate 2–3 outfit previews using owned items + the candidate. Candidate products come from the same Lens/grounding layer (step 2–3). No catalog partner needed.
- Guardrails: never rank by commission; disclose; offer "buy nothing" answers explicitly (differentiator vs Alta/Essembl per competitors.md).

**Wishlist**
- Share-sheet/paste URL → server fetch (user-initiated) → JSON-LD `Product/Offer` → fallback Gemini `url_context` → store item; "re-check price" button (same path); Amazon URLs: store ASIN + link out, no price polling.
- Legal MVP checklist: 5.1.2(i) consent screen for third-party AI + SerpApi; privacy label; FTC disclosure component; no IAP for goods; account deletion.

### Phase 1 — 3–6 months (networks, catalog, price tracking)
1. Apply immediately (approvals take weeks): **Awin** (deposit, EU), **Impact.com** (US DTC brands; request catalog API), **CJ**, **Rakuten** (dept stores), **Tradedoubler** (Inditex), **eBay EPN + Buy API** (secondhand angle; business-model review), **Amazon Associates** (start the 3-sales/180-day clock via wrapped links; Creators API only after 10 sales/30 days).
2. Build the **licensed catalog**: ingest Awin Enhanced JSONL + Impact/CJ feeds into your DB; per-advertiser health/kill switch; store `aw_deep_link`/`linkCode` verbatim (never compose tracking URLs); TTL per network; image hotlinking, no derivative images.
3. **Visual similarity index** over the catalog (Marqo-FashionSigLIP or gemini-embedding-2) → for covered merchants replace SerpApi with your index (commission + no scraping); keep Lens for the long tail.
4. **Price tracking** from feeds (daily) with Mercaria-style dedupe keys and repeat policies; push notifications; Amazon excluded unless Creators API is live (then 24 h rule + timestamps).
5. Ranking transparency (EU Omnibus): document ranking parameters in-app.

### Phase 2 — 6–12+ months
- Direct brand deals (licensed imagery → try-on on recommended products, like Alta); Shopify per-store MCP catalogs for partner brands; **agentic checkout** as a UCP/ACP client when EU/third-party-agent programmes open (no commission model yet — negotiate); Amazon Creators API if volume thresholds are met; resale (eBay Browse/EPN, Vinted) for "sell what you don't wear"; Israel: AliExpress Affiliate + direct deals with local chains; consider CPC/sponsored placement only with clear labelling (Polyvore lesson: CPC out-earned affiliate).

### Unit-economics sanity check
Fashion affiliate 4–10 % (Amazon apparel 4 %; eBay 1–4 %; DTC brands often 5–12 %); AOV $60–150; click→purchase 1–3 %; returns 20–30 % claw back → **EPC ≈ $0.05–0.20**, minus Skimlinks' 25 % in Phase 0. Affiliate is a complement to subscription, not the core (consistent with dotfyles India analysis and Whering/Alta strategies).
