## 2. Vision framework on-device (cutout, pose, person segmentation, subject lift)

Apple docs mirror (`apple-dev-docs/documentation/Vision`, snapshot 2026-09-04):

- **`GenerateForegroundInstanceMaskRequest`** (Swift-native struct, iOS 18.0+; ObjC `VNGenerateForegroundInstanceMaskRequest` iOS 17+): "generates an instance mask of noticeable objects to separate from the background". Run with `try await GenerateForegroundInstanceMaskRequest().perform(on: cgImage, orientation:)`. Result **`InstanceMaskObservation`** exposes `allInstances: IndexSet` ("all instances, excluding the background"), `allInstancesMask`, `instanceAtPoint(NormalizedPoint) -> IndexSet`, `generateMask(for: IndexSet)` (low-res), `generateScaledMask(for:scaledToImageFrom: ImageRequestHandler)` (high-res), and **`generateMaskedImage(for: IndexSet, imageFrom: ImageRequestHandler, croppedToInstancesExtent: Bool) -> CVPixelBuffer`** ("high-resolution image with everything except for the instances you specify masked out"). **[high]**
  - Multi-item: the observation is an *instance* mask, so multiple garments laid out flat come back as separate indices; pick with `instanceAtPoint` or iterate `allInstances`. Real-world code (raycast/extensions remove-background, ddalcu/mlx-serve SubjectCutout, Snapzy ForegroundCutoutService) all use `generateMaskedImage(ofInstances: result.allInstances, from: handler, croppedToInstancesExtent: false)` and then `CIImage(cvImageBuffer:)`. Sources: https://github.com/raycast/extensions (extensions/remove-background-powered-by-mac/Sources/main.swift), https://github.com/ddalcu/mlx-serve. **[high]**
  - Output is RGBA with transparent background; compose over white with Core Image (`CIImage.composited(over: CIImage(color: .white))`). Quality: Apple documents no accuracy figure; community consensus is that it is the same "subject lift" model as Photos - excellent for clearly separated objects, weaker on fine edges (lace, mesh, fur), very thin straps, white garments on white/light backgrounds, and cluttered flat-lays. **[medium]** Recommendation: on-device by default; cloud (Gemini image model or a dedicated matting API) as an "enhance" or fallback when the mask area is tiny/empty or the user rejects the result.
- **`GeneratePersonSegmentationRequest`** (class, iOS 18+; `VNGeneratePersonSegmentationRequest` iOS 15+): `qualityLevel` (`.fast/.balanced/.accurate`), `outputPixelFormat`; produces a person matte. **`GeneratePersonInstanceMaskRequest`** (iOS 18+): "a mask of individual people" (up to a handful of people). Use for try-on/avatar photos, not for garments. **[high]**
- **`DetectHumanBodyPoseRequest`** (struct, iOS 18+) -> `HumanBodyPoseObservation` with `JointName` (`.leftShoulder`, `.rightHip`, ...); 3D variant `DetectHumanBodyPose3DRequest`. Good for capture guidance ("stand inside the outline") and for validating a full-body photo before sending it to a try-on model. Source: docs mirror + https://github.com/Ale-Coeto/OpenClimb usage. **[high]**
- **Iterative segmentation** (new): "Segmenting objects using taps, scribbles or rectangles ... `GenerateIterativeSegmentationRequest`" is listed as a sibling of the foreground request in the 2026-09-04 docs snapshot - a tap/scribble refine step for garment masks (OS availability not captured in the snapshot; likely iOS 26 or 27). **[medium]**
- **VisionKit subject lifting**: `ImageAnalysisInteraction` with `preferredInteractionTypes = .imageSubject` gives the system long-press "lift subject" UX; `ImageAnalysisInteraction.subjects: Set<Subject>` (iOS 16+), `subject(at: CGPoint)`, and `image(for: Set<Subject>) async throws -> UIImage` ("contains the given subjects with the background removed"). Live Text = `.textSelection` / `.dataDetectors`. Sources: docs mirror `VisionKit/imageanalysisinteraction/subjects.md`; https://github.com/signerlabs/ShipSwift; https://github.com/HuangRunHua/wwdc23-code-notes. **[high]**
- **Can it replace the cloud "white background cutout" call?** For the *segmentation* step, yes for most photos (free, ~100-300 ms, offline, no privacy disclosure). It cannot: relight/"ghost mannequin" the garment, fix wrinkles, standardize the pose, or fill occluded parts - those remain generative-cloud tasks. Plan: on-device mask -> white composite -> optional cloud "studio enhance" (Gemini image model) as a premium feature. **[medium]**

## 3. Foundation Models (on-device LLM) and Apple Intelligence

Apple docs mirror (`apple-dev-docs/documentation/FoundationModels`, 2026-09-04) unless noted:

- **Context window**: "Apple's on-device foundation model has a context window of 4096 tokens per session ... This includes all prompts, instructions, tool definitions and their input and output, generable type schemas, and all of the model's responses." Exceeding it throws `LanguageModelError.contextSizeExceeded(_:)` (iOS 27 naming; iOS 26 code sees `LanguageModelSession.GenerationError.exceededContextWindowSize`). `SystemLanguageModel.contextSize` and `tokenCount(for:)` exist. Recovery: `LanguageModelSession(model:tools:transcript:)` with a trimmed transcript. Source: `managing-the-context-window.md`; Xcode 27 bundle `FoundationModels-Using-on-device-LLM-in-your-app.md` ("The system model supports up to 4,096 tokens per session"). **[high]**
- **Model versions**: "Currently, there are 3 model versions that align with: iOS/iPadOS/macOS/visionOS 26.0-26.3; 26.4; 27.0" - prompts should be re-evaluated per version (`updating-prompts-for-new-model-versions.md`). **[high]**
- **Availability**: `SystemLanguageModel.default.availability` -> `.available` / `.unavailable(.deviceNotEligible | .appleIntelligenceNotEnabled | .modelNotReady)`. Requires Apple Intelligence-capable device + toggle on + supported region/language. **[high]**
- **Guided generation**: `@Generable`, `@Guide(description:, .range(...), .maximumCount(...), .count(...))`, `session.respond(to:generating:)`, snapshot streaming `streamResponse(to:generating:)` yields `PartiallyGenerated` types; tool calling via `Tool` protocol (`Arguments: Generable`, `call(arguments:) -> ToolOutput`/String); `GenerationOptions(temperature:)`, `samplingMode: .greedy`. **[high]**
- **Content tagging** (ideal for wardrobe tag extraction from a description or from OCR/label text): `SystemLanguageModel(useCase: .contentTagging)` "identifies topics, actions, objects, and emotions" and returns 1-few-word lowercase tags; pair with a `@Generable` struct using `.maximumCount`. Source: `categorizing-and-organizing-data-with-content-tags.md`. **[high]**
- **Image input**: **iOS 26: text only. iOS 27: multimodal** - `Attachment(cgImage)` / `Attachment(imageURL:orientation:)` inside a `Prompt` builder ("The Foundation Models framework supports using text and images in your prompts"), `ImageReference` for tools, built-in Vision `OCRTool` / `BarcodeReaderTool`; `Attachment` is "iOS 27.0+ (Beta)". Example in Apple's doc is literally `@Generable enum ImageLabel { case cat ... }` classification with `GenerationOptions(samplingMode: .greedy)` - directly reusable for garment category/colour/pattern tagging offline on iOS 27. Sources: `analyzing-images-with-multimodal-prompting.md`, `attachment.md`. **[high]**
- **iOS 27 `LanguageModel` protocol & Private Cloud Compute**: `LanguageModelSession(model:)` now accepts any `LanguageModel` (`SystemLanguageModel`, `PrivateCloudComputeLanguageModel`, third-party adapters such as Firebase's `GeminiLanguageModel`, Anthropic's `ClaudeForFoundationModels`, `mlx-swift-lm`). `LanguageModelCapabilities.Capability` = `.guidedGeneration, .reasoning, .toolCalling, .vision`. **PCC**: "32K-token context size and stronger reasoning", "Usage limits: Limit per day", `ContextOptions(reasoningLevel: .light/.moderate/.deep)`, `quotaUsage.status / isLimitReached / resetDate / limitIncreaseSuggestion.show()` (upsells iCloud+), errors `PrivateCloudComputeLanguageModel.Error.quotaLimitReached/networkFailure/serviceUnavailable`, requires the **managed entitlement `com.apple.developer.private-cloud-compute`** ("To develop with PCC you must meet certain eligibility requirements ... request access"). Sources: `adding-server-side-intelligence-with-private-cloud-compute.md`, `languagemodelcapabilities.md`, https://github.com/rryam/FoundationModelsKit (PrivateCloudComputeEntitlementChecker.swift), https://github.com/anthropics/ClaudeForFoundationModels. **[high]**
- **Languages**: "the same model understands and generates text in any language that Apple Intelligence supports"; check `SystemLanguageModel.default.supportsLocale()` / `supportedLanguages`. Apple Intelligence languages as of iOS 26: English, French, German, Italian, Portuguese (BR), Spanish, Japanese, Korean, Chinese (Simplified), plus Danish, Dutch, Norwegian, Portuguese (PT), Swedish, Turkish, Chinese (Traditional), Vietnamese - **Hebrew is not supported** (support page https://support.apple.com/en-us/121115 is blocked; list from memory) **[medium]**. For an Israeli/Hebrew UI, on-device LLM features must degrade to cloud Gemini.
- **Image Playground** (iOS 18.1+): `.imagePlaygroundSheet(isPresented:concept:sourceImage:onCompletion:onCancellation:)`, `ImagePlaygroundConcept`, `ImagePlaygroundViewController`, styles Animation/Illustration/Sketch; "programmatic interface to generate images without interactions" (`ImageCreator`). It produces stylised, non-photoreal images and does **not** do try-on or realistic garment renders - only useful for fun avatars/stickers. Source: docs mirror `ImagePlayground/ImagePlayground.md`. **[high]**
- Siri/Apple Intelligence personal context in iOS 27 reportedly uses Gemini-based models; the `GeminiLanguageModel` module in the Firebase repo (`GeminiLanguageModel/Sources/GeminiLanguageModel/GeminiLanguageModel.swift`, `@available(iOS 27.0...)`, "A Gemini language model adapter conforming to Apple's `FoundationModels.LanguageModel` protocol", capabilities `[.reasoning]`, translator throws on `.attachment` segments = **no image attachments yet through this adapter**) is Google's official adapter. **[high for the adapter; low for Siri internals]**

## 4. Core ML

- coremltools 9.0 (GA ~Nov 2025 per the releases page; year inferred) adds "iOS26/macOS26/watchOS26/tvOS26 deployment targets", int8 I/O, model state. No coremltools 10 GA yet in the releases list. Source: https://github.com/apple/coremltools/releases. **[medium]**
- Create ML image classifier / Vision `CoreMLRequest` (iOS 18 Swift API) is the cheapest way to add an offline garment-category classifier; but with iOS 27 multimodal Foundation Models you can classify via `@Generable enum` without shipping a model. Recommendation: skip a custom Core ML model at launch. **[medium]**

## 5. Photos, camera, Live Text

- **PhotosPicker** (`import PhotosUI`, `PhotosPicker(selection: $items, maxSelectionCount:, matching: .images)`, `PhotosPickerItem.loadTransferable(type: Data.self)`) runs out-of-process and needs **no photo-library permission**; only add `NSPhotoLibraryUsageDescription` if you use `PHPhotoLibrary` (limited-library mode `PHPhotoLibrary.requestAuthorization(for: .readWrite)` with `.limited`), and `NSPhotoLibraryAddUsageDescription` for saving. Guideline 5.1.1(iii): "Where possible, use the out-of-process picker or a share sheet rather than requesting full access to protected resources like Photos". **[high]**
- **Camera capture with guidance**: `AVCaptureSession` in a `UIViewRepresentable` with a SwiftUI overlay (silhouette outline for garments/body); run `DetectHumanBodyPoseRequest` on frames to gate the shutter; `NSCameraUsageDescription` required; guideline 2.5.14 requires a clear visual indication while recording. **[high]**
- **Live Text / OCR**: `ImageAnalyzer` + `ImageAnalysisInteraction` (`.textSelection`), or Vision `RecognizeTextRequest` / (iOS 26) `RecognizeDocumentsRequest`; iOS 27 adds Foundation Models `OCRTool` for reading care labels inside an LLM session. **[high]**

## 6. WeatherKit, CoreLocation, EventKit, Widgets/Live Activities, App Intents, Push, BackgroundTasks

- **WeatherKit**: `let weather = try await WeatherService.shared.weather(for: CLLocation(...))`; `weather.currentWeather.temperature/symbolName`, `dailyForecast`. **Attribution is mandatory**: "Attribution is required for publishing software using WeatherKit" - `let attribution = try await WeatherService.shared.attribution`, show `attribution.combinedMarkLightURL/DarkURL` (Apple Weather logo) and link `attribution.legalPageURL` (or `legalAttributionText`). Source: docs mirror `WeatherKit/weatherattribution.md`; https://github.com/apple/sample-food-truck (App/City/CityView.swift). Pricing **[memory, medium]**: 500,000 calls/month included with the Apple Developer Program; paid tiers 1M $49.99, 2M $99.99, 5M $249.99, 10M $499.99, 20M $999.99 per month (verify at https://developer.apple.com/weatherkit/get-started/). Needs the WeatherKit capability + App ID service enabled.
- **CoreLocation**: `CLLocationManager.requestWhenInUseAuthorization()`, iOS 17+ `CLLocationUpdate.liveUpdates()`; use "when in use" only (guideline 5.1.1(iv): offer manual city entry if declined). **[high]**
- **EventKit**: iOS 17+ `EKEventStore.requestFullAccessToEvents()` / `requestWriteOnlyAccessToEvents()`; `NSCalendarsFullAccessUsageDescription` / `NSCalendarsWriteOnlyAccessUsageDescription`; consider `EKEventEditViewController` (no permission needed) for "add outfit reminder". **[high]**
- **Widgets/Live Activities**: WidgetKit with Liquid Glass ("WidgetKit-Implementing-Liquid-Glass-Design.md" in the Xcode 27 bundle); ActivityKit `Activity.request(attributes:content:pushType:)`; `BGContinuedProcessingTask` automatically shows progress "in a Live Activity" (see below). Guideline 2.5.16: widgets must relate to the app's content. **[high]**
- **App Intents / Siri / Shortcuts / Visual Intelligence**: `AppIntent`, `AppShortcutsProvider`, `AppEntity` + `IndexedEntity` (Spotlight), `IntentValueQuery` with `SemanticContentDescriptor` (VisualIntelligence framework, iOS 26: "labels: [String]" + "pixelBuffer") lets the system camera/screenshot search your wardrobe ("find this jacket in my closet"); iOS 27 adds `@UnionValue`, interactive snippets updates, on-screen entities. Sources: Xcode 27 bundle `AppIntents-Updates.md`, `app-intents-whats-new-27-ref-visual-intelligence.md.packaged`. Guideline 2.5.11: only register intents the app can fulfil itself; vocabulary must relate to the app. **[high]**
- **Push**: APNs token-based auth (`.p8`), `UNUserNotificationCenter.requestAuthorization`, provisional auth for quiet delivery; Firebase Messaging optional (12.18.0 deprecates legacy FCM token APIs "in favor of new FID-based registration"). Guideline 5.1.2(i): you may not require push to be enabled to use the app. **[high]**
- **BackgroundTasks**: `BGContinuedProcessingTask` (iOS 26.0+) "starts in the foreground and can continue running in the background as needed. The system displays the progress of this task in a Live Activity and a person can cancel it"; must report `Progress`; request via `BGContinuedProcessingTaskRequest(identifier:title:subtitle:)`, `request.strategy = .queue`, `BGTaskScheduler.shared.submit(request)`; optional GPU entitlement `com.apple.developer.background-tasks.continued-processing.gpu`. Use it for "process 40 photos into cutouts". `BGProcessingTaskRequest` (`requiresNetworkConnectivity`, `requiresExternalPower`) for nightly re-sync. Sources: docs mirror `BackgroundTasks/bgcontinuedprocessingtask.md`; https://github.com/Aidoku/Aidoku, https://github.com/ente/ente usage. **[high]**

## 7. StoreKit 2, offers, paywalls, Family Sharing, server notifications, RevenueCat

- **StoreKit 2 essentials**: `Product.products(for:)`, `product.purchase()`, `Transaction.updates`, `Transaction.currentEntitlements(for:)` (iOS 18.4+ replaces `currentEntitlement(for:)`), `AppTransaction.shared` (`appTransactionID`, `originalPlatform`, back-deployed to iOS 15), `Product.SubscriptionInfo.Status(transactionID:)`, `renewalInfo.expirationReason` (`.priceIncrease`, `.billingError`) for win-back logic, `AppStore.sync()` for restore. Source: Xcode 27 bundle `StoreKit-Updates.md`. **[high]**
- **Paywall views**: `SubscriptionStoreView(groupID:)` / `(productIDs:)` with `.subscriptionStoreControlStyle(.compactPicker, placement: .buttonsInBottomBar)` / `.prominentPicker`, `SubscriptionPeriodGroupSet`, `.storeButton(.visible, for: .restorePurchases)`; new **`SubscriptionOfferView(productID:)`** with `visibleRelationship: .upgrade/.downgrade/.crossgrade/.current/.all`, `.subscriptionOfferViewDetailAction {}`; `.subscriptionStatusTask(for: groupID)` to drive entitlement state. Sources: `StoreKit-Updates.md`; https://github.com/jordibruin/StoreKit-Examples. **[high]**
- **Intro / promotional / win-back offers**: introductory offer eligibility `product.subscription?.isEligibleForIntroOffer`; "StoreKit now requires JSON Web Signatures (JWS) for certain Purchase Option and View Modifier APIs: Setting customer eligibility for introductory offers; Signing promotional offers" - sign on your server with `apple/app-store-server-library-swift` (`PromotionalOfferSignatureCreator`, Swift 6 required). Win-back offers (iOS 18) configured in App Store Connect. **[high]**
- **Family Sharing**: enable per subscription in App Store Connect; `appTransactionID` is "Unique for each family group member for apps supporting Family Sharing"; `Transaction.ownershipType == .familyShared`. **[high]**
- **App Store Server Notifications V2 + Server API**: `apple/app-store-server-library-swift` provides `AppStoreServerAPIClient`, `SignedDataVerifier` (verify JWS notifications with Apple root certs), `ReceiptUtility`; "Only the latest major version of the library will receive updates". Source: https://raw.githubusercontent.com/apple/app-store-server-library-swift/main/README.md. **[high]**
- **RevenueCat vs native**: purchases-ios 5.88.0 (released 2026-09-03; changelog "Surface attribute sync errors when fetching offerings", web-view paywalls, "checkpoint" local rules engine, AdMob reward adapters), min iOS 13 / Xcode 15. Pricing **[memory, medium]**: free up to $2.5k monthly tracked revenue, then ~1% of MTR. Choose RevenueCat if you want hosted paywall templates/A-B tests, cross-platform entitlement backend and no server code; choose native StoreKit 2 + `app-store-server-library` if iOS-only and you already run Cloud Functions - both are guideline-compliant. Sources: https://github.com/RevenueCat/purchases-ios/releases, README. **[high for versions]**

Changes since 2025 per https://github.com/viralapplabs/app-review-guidelines-changelog: wave 2026-07-01 reworded 1.2 (UGC), 2.5 (Software Requirements), 4.3 (Spam), 4.5 (Apple Sites and Services), 4.8 (Login Services). A community fork notes an "Aug 2026 ... Guideline 5.6.3 onboarding review-prompt ban" (https://github.com/timiabiola/app-store-review-skill) - the snapshot's 5.6.3 text ("Manipulating any element of the App Store customer experience such as charts, search, reviews, or referrals ... is not permitted") does not spell out onboarding rating prompts, so treat "no `requestReview()` during onboarding" as best practice **[medium]**.

Relevant clauses (verbatim excerpts):
- **1.2 User-Generated Content**: apps with UGC/social must include "A method for filtering objectionable material", "A mechanism to report offensive content and timely responses", "The ability to block abusive users", "Published contact information". If you add outfit sharing/community, all four are mandatory. **1.2.1 Creator Content** (new): creator apps "must provide a way for users to identify content that exceeds the app's age rating, and use an age restriction mechanism based on verified or declared age". **[high]**
- **AI-generated content / people's likeness**: there is **no** dedicated "AI" guideline; the only explicit AI text is **5.1.2(i)**: "You must clearly disclose where personal data will be shared with third parties, **including with third-party AI**, and obtain explicit permission before doing so." Photos of the user's body sent to Gemini/any try-on API = personal data shared with third-party AI -> explicit in-app consent screen + privacy policy disclosure + App Privacy label. Generated images of *real people* are governed by 1.1 (objectionable content: 1.1.2 realistic violence, 1.1.4 sexual content), 1.2 (no "objectification of real people (e.g. 'hot-or-not' voting)") and 5.1.2(vi) (data "from depth and/or facial mapping tools (e.g. ARKit, Camera APIs, or Photo APIs) may not be used for marketing, advertising or use-based data mining"). Practical: only allow try-on on the user's own photos, add a "generated with AI" label, block nudity/underwear generation, provide report/delete. **[high]**
- **2.5.1** public APIs only, "must run on the currently shipping OS"; **2.5.4** background modes only for intended purposes (`BGContinuedProcessingTask` is fine for user-initiated batch); **2.5.11** Siri/Shortcuts scope; **2.5.13** Face ID for account auth must use LocalAuthentication and an alternate method for under-13; **2.5.14** explicit consent + visible indicator when using camera; **2.5.16** widgets must relate to app content; **2.5.18** ads limited to main binary, no sensitive-data targeting. **[high]**
- **3.1.1**: unlocking features must use IAP; "you should make sure you have a restore mechanism"; **3.1.2(a)**: subscription "must provide ongoing value", "period must last at least seven days and be available across all of the user's devices"; free trials via App Store Connect offers; **3.1.2(c)**: "Before asking a customer to subscribe, you should clearly describe what the user will get for the price"; **3.1.1(a)**: US storefront may include external purchase links without an entitlement. **[high]**
- **4.7 Mini apps, mini games, streaming games, chatbots, plug-ins, and game emulators**: applies only if you host third-party HTML5/JS software or chatbots not embedded in the binary; an in-house AI stylist chat is *not* a 4.7 "chatbot" plug-in, but if you ever let brands ship their own stylist bots you must meet 4.7.1-4.7.5 (index with universal links, age gating, no native API exposure). The "Mini Apps Partner Program" (15% commission) is referenced in Apple's Nov/Dec 2025 announcements **[memory, medium]**. **[high for the text]**
- **4.8 Login Services**: "Apps that use a third-party or social login service (such as Facebook Login, Google Sign-In, ...) to set up or authenticate the user's primary account with the app must also offer as an equivalent option another login service" that limits data to name+email, lets users hide email, and doesn't collect interactions for ads - i.e. **Sign in with Apple** (or equivalent). Not required if "Your app exclusively uses your company's own account setup and sign-in systems" (email/password or passkeys only). **[high]**
- **5.1.1(i)** privacy policy link in metadata and in-app, must "Explain its data retention/deletion policies and describe how a user can revoke consent and/or request deletion"; **(ii)** consent for usage data, "Paid functionality must not be dependent on ... access to this data"; **(iii)** data minimization / prefer out-of-process picker; **(iv)** offer alternatives when permission denied; **(v)**: "If your app doesn't include significant account-based features, let people use it without a login. If your app supports account creation, you must also offer account deletion within the app"; **(ix)** highly regulated fields must be submitted by a legal entity (not applicable to fashion). **[high]**
- **5.1.2(i)** also: "You must receive explicit permission from users via the App Tracking Transparency APIs to track their activity" and "Your app may not require users to enable system functionalities (e.g. push notifications, location services, tracking) in order to access functionality". **[high]**

## 9. Privacy

- **Privacy manifest** `PrivacyInfo.xcprivacy` (app + every SDK): keys `NSPrivacyTracking`, `NSPrivacyTrackingDomains`, `NSPrivacyCollectedDataTypes`, `NSPrivacyAccessedAPITypes`. "Starting May 1, 2024, apps that don't describe their use of required reason API in their privacy manifest file aren't accepted by App Store Connect." Required-reason categories you will hit: `NSPrivacyAccessedAPICategoryUserDefaults` (reason `CA92.1`), `FileTimestamp` (`C617.1`), `DiskSpace` (`E174.1`), `SystemBootTime` (`35F9.1`). Firebase/RevenueCat ship their own manifests. Source: docs mirror `BundleResources/privacy-manifest-files.md`, `describing-use-of-required-reason-api.md`. **[high]**
- **Privacy nutrition labels** (App Store Connect) must match the manifest-generated privacy report; declare Photos, Purchases, Usage Data, Identifiers (if analytics), "Other user content" (AI chat), and mark "Data Linked to You" appropriately. **[high]**
- **ATT**: only needed if you track across apps/sites (ad SDKs); avoid it - use privacy-preserving analytics (Firebase Analytics without IDFA, or TelemetryDeck). **[high]**
- **Photos**: prefer `PhotosPicker`; if using PHPhotoLibrary support the limited-library selection UI (`PHPhotoLibrary.shared().presentLimitedLibraryPicker(from:)`), set `PHPhotoLibraryPreventAutomaticLimitedAccessAlert`. **[high]**
- **Face ID**: `LAContext.evaluatePolicy(.deviceOwnerAuthenticationWithBiometrics)`, `NSFaceIDUsageDescription`; per 2.5.13 provide a fallback for under-13s. **[high]**
- **Deletion**: 5.1.1(v) in-app account deletion; implement server-side purge (Firestore/Storage/CloudKit + AI logs) and honour Google's Gemini data-retention settings (AI Logic requests via the Firebase proxy are not used for training on paid tiers **[medium]**).
- **Body/face photos sent to cloud**: treat as sensitive; consent screen, disclose "shared with Google (Gemini) for processing", keep originals on-device/CloudKit, send downscaled copies. **[high]**

## 10. Security: protecting backend endpoints

- **Never ship the Gemini key.** Firebase AI Logic routes every call through the Firebase proxy (`firebaseProxyProd`, API v1beta) with the project's public Firebase API key, which can be restricted by iOS bundle ID (`x-ios-bundle-identifier` header, Firebase 12.7.0). A Hacker News-reported incident (2026-04-16 digest) shows the failure mode: an unrestricted key "Within ~13 hours, automated traffic hammered the Gemini API"; the takeaway there: "App Check doesn't protect non-Firebase Google APIs; use server-side enforcement". Source: https://github.com/Planeshifter/hackernews-ai-digest (data/digest_2026-04-16.md); FirebaseAI CHANGELOG 12.7.0. **[high]**
- **Firebase App Check**: became a hard dependency of Firebase AI Logic in **12.15.0 (June 2026)** "to simplify App Check setup"; SDK sends `X-Firebase-AppCheck`; enforcement is toggled per product (AI Logic) in the console; `FirebaseAI.firebaseAI(backend:useLimitedUseAppCheckTokens:)` `= true` sends limited-use tokens ("required for an upcoming optional feature called replay protection"). Production providers: **App Attest** (`AppAttestProviderFactory`, iOS 14+) with **DeviceCheck** fallback; debug provider only for dev (quickstart warns "Before distributing your app to the App Store, you must migrate to a production-grade provider"). The task premise "enforcement mandatory since July 2026" could not be verified from any fetched source (firebase.google.com blocked); the SDK evidence (dependency added June 2026; Android changelog fix for "requests being rejected when App Check is enforced on AI Logic") is consistent with enforcement being expected/default for new projects **[medium]**. Sources: `firebase-ios-sdk/FirebaseAI/CHANGELOG.md`, `FirebaseAI/Sources/FirebaseAI.swift`, https://github.com/firebase/quickstart-ios (firebaseai/README.md), https://github.com/firebase/firebase-android-sdk (ai-logic/firebase-ai/CHANGELOG.md).
- **Your own endpoints (Cloud Functions/Run)**: use App Check tokens (`AppCheck.appCheck().token(forcingRefresh:)`) *or* raw **App Attest**: `DCAppAttestService.shared.isSupported`, `generateKey()`, `attestKey(keyId, clientDataHash:)`, `generateAssertion(keyId, clientDataHash:)`, server verifies with Apple's App Attest root CA; Apple: "Don't reuse a key among multiple users on a device". Also forward the Firebase Auth ID token so per-user quotas can be enforced server-side (AI Logic already forwards Auth via `FirebaseAuthInterop`). Sources: docs mirror `DeviceCheck/establishing-your-app-s-integrity.md`; https://github.com/anthropics/ClaudeForFoundationModels (AttestationService.swift), https://github.com/stripe/stripe-ios. **[high]**
- Add server-side rate limits per uid + per App Check token, budget alerts on the Gemini project, and Remote Config kill-switches for expensive features. **[high]**

## 11. Sync / storage

- **SwiftData + CloudKit** (`ModelConfiguration(schema:, cloudKitDatabase: .private("iCloud.com.yourco.app"))`): requires iCloud + Background Modes (remote notifications) capabilities; "CloudKit is unable to enforce the `unique` property option"; "CloudKit requires all relationships to be optional"; `.deny` delete rule unsupported; "CloudKit schemas are additive only ... promote that schema to production before releasing". iOS 26 adds `@Model` class inheritance (e.g. `Garment: WardrobeItem`) - fine for CloudKit as long as the rules above hold. Store images with `@Attribute(.externalStorage) var imageData: Data?` (thumbnails inline, full-res external) - CloudKit turns them into `CKAsset`s; keep the private DB only (no sharing needed at MVP). Sources: docs mirror `SwiftData/syncing-model-data-across-a-persons-devices.md`; Xcode 27 bundle `SwiftData-Class-Inheritance.md`; https://github.com/mierau/hotline usage. **[high]**
- **Firestore + Cloud Storage** alternative: offline persistence on by default, 16 MB documents (12.17.0), image bytes in Storage with security rules keyed on `request.auth.uid` and App Check. Choose Firestore if (a) you need Android/web later, (b) the backend must read wardrobe data for server-side AI (CloudKit is hard to reach from Cloud Functions - CloudKit Web Services/server-to-server keys exist but are clunky), or (c) you want shareable public looks. Choose SwiftData+CloudKit if iOS-only, privacy-first, zero backend cost. A pragmatic hybrid: SwiftData local store (offline-first UI) + your own sync to Firestore. **[medium]**
- **Offline-first**: all catalogue CRUD, on-device cutouts, and content-tagging via Foundation Models work offline; queue cloud jobs (try-on, enhance, chat) with a persistent job table + `BGProcessingTask` retry. **[high]**
